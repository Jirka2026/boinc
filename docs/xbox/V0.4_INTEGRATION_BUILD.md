# BOINC Xbox v0.4 - Integration build

This build combines several previously separate milestones into one Xbox test cycle.

## One-run integration suite

The **Run full integration test** button checks:

1. BOINC project configuration (`get_project_config.php`).
2. Master page parsing and scheduler discovery.
3. Raw TCP reachability of the discovered scheduler.
4. BOINC account lookup using the standard `MD5(password + lowercase email)` password hash.
5. Secure storage of the returned project authenticator in Windows `PasswordVault`.
6. A CPU benchmark using all logical processors visible to the UWP runtime.
7. Current UWP memory limit and a 90 percent memory high-water policy.
8. LocalSettings write/read persistence.

The plaintext password is never saved. It is hashed immediately for the BOINC lookup request, cleared from the password field, and only the returned authenticator is persisted in PasswordVault.

## Persisted state

The build persists project URL, project name, master URL, server version, scheduler URL and account email in LocalSettings. The BOINC authenticator is stored separately in PasswordVault.

## Performance policy

The CPU benchmark intentionally starts one worker per logical processor reported by the Xbox runtime. Future science workers will use the same runtime-driven policy rather than a fixed CPU count.

The app does not allocate the entire memory limit during diagnostics. It records a 90 percent high-water mark to leave safety headroom below the UWP hard cap.

## Next integration milestone

The next build will use the stored authenticator and discovered scheduler URL to perform the first real BOINC scheduler RPC, collect the server response for the Xbox platform, and begin the work-download/science-worker pipeline.
